## C9 Weekly AAR — Week 2（2026-10-08）

### 做了什么
- **本周产出**：Pulse V1 —— 多周 JSON 数据层（`data/weeks.json`）、`list` 命令、`analyze` 命令、文本动力曲线（ASCII chart）与最小二乘趋势斜率。动力序列第一次可视化：`[7, 8]`。
- **公开在哪里**：Elite20 群（发布"我的 AAR 有动力曲线了"的截图）。
- **关键动作**：从"单周快照"升级到"多周趋势"，验证了核心假设——**数据确实能讲出故事**。

### 哪些有效
- **命令分离的设计**有效：把 `list` / `analyze` / 后续 `dashboard` 拆成子命令，结构清晰，加功能时互不干扰。
- **自己实现斜率算法**有效：放弃对库版本的依赖后，代码在任何 Python 3.8+ 环境都能跑，可移植性大幅提升。
- **ASCII 文本曲线**作为过渡形态很有效：零依赖、终端立即可见，是可视化前的低成本验证。

### 哪些无效
- **踩了版本兼容的坑**：初版斜率想直接调用 `statistics.linear_regression`，但那是 Python 3.10 才引入的，我的环境是 3.9，运行即报错。
  - **为什么失败**：对标准库 API 的版本历史不熟，且没先查文档就用。
  - **如何修**：手写了 6 行最小二乘实现（`slope()`），无依赖、可测试，反而更稳。教训：**"拿来"一个 API 前先确认它的可用性边界**。
- **数据 schema 没做版本字段**：为后续数据迁移埋了小隐患（W7 补 upper 了约束说明，但未加 schema version，属已知局限）。

### 动力检查

- **动力变化原因**：曲线成形的那一刻，我做这件事的底层假设——"反思可以被量化"——第一次被实证。我看到数据能量化自己的状态，这种"发现新大陆"的感觉极强。
