## 1. 项目定义

- **我想做什么（一句话）**：做一个把每周 AAR 变成可测量"生命体征"、并自动预警"缓慢死亡"的个人成长命令行工具——**Pulse**。
- **输入**：每周 AAR 的结构化记录（本周产出、有效/无效方法、1–10 的动力分数、动力变化原因、下周计划、公开渠道）。
- **输出**：① 动力曲线与趋势斜率；② 缓亡风险分（0–100）与分级预警；③ 自包含的 HTML 可视化仪表盘；④ 可导出的 8 周复盘数据（CSV/JSON）。
- **为什么这件事重要**：
  - **对我**：我同时在跑 C8 真实项目和 C9 自驱项目，亲身体会到 AAR 极易写得敷衍、动力下滑难以察觉、拖到最后"忘了自己曾经想做什么"。CHALLENGE.md 里那句"最大的敌人不是失败，是缓慢死亡"击中了要害——我有强烈需求想把这条洞察**变成一套真的会报警的系统**。一个运行良好的个人系统是所有其他能力的放大器。
  - **对他人/世界**：所有做长期项目、自律系统、独立开发的人都需要"早期预警"。市面上的日记/习惯 App 要么只记录不分析，要么只统计打卡次数而不关心"反思质量"和"动力趋势"。Pulse 把 AAR 方法论沉淀为一个开源、零依赖、人人可用的工具。
- **这个东西目前存在吗**：
  - **存在相近物**：Notion/Obsidian 可以搭 AAR 模板，Day One 可以记日记，Habitica/Streaks 可以打卡（详见第 2 部分与《拿来说明》）。
  - **但没有人把它做成"面向 AAR 的缓亡预警系统"**。为什么之前没人做：
    1. AAR 是相对小众的方法论语言（Elite20 内部术语），通用产品不会为它专门设计；
    2. "动力分数"是主观数据，主流量化产品嫌其"不科学"而回避——但**主观数据的趋势本身就有信号价值**，这是被忽视的空白；
    3. 需要同时懂反思方法论、会写代码、又有真实使用动机的人，交叉地带人很少；
    4. 市场太小、不赚钱 → 公司不会做，但这恰恰使它是理想的**个人自驱项目**。
  - **我凭什么能做成**：我正身处最需要它的场景（C9 本身），拥有"第一用户 + 开发者"的双重身份，反馈闭环最短；AI 工具让我能把想法快速落地为可运行代码；我愿意把它真正做到"自己天天用"的程度，而不是一次性作业。

## 2. 拿来主义分析

> 即使这个点子对我而言是原创的，我依然强制自己做了竞品调研——绝不能闭门造车。完整对比见《赵心皓_C9_拿来说明.md》。

### 竞品 / 参考项目

| 名称 | 链接 | 它做了什么 | 做得好的地方 | 做得不好的地方 |
|------|------|-----------|--------------|----------------|
| Notion AAR/周报模板 | notion.so | 用数据库+模板做周报与复盘 | 灵活、模板生态丰富、协同强 | 通用工具，不内置动力分析/预警；依赖云端；结构全靠自己搭 |
| Obsidian + Dataview | obsidian.md | 本地 Markdown 双链 + 查询统计 | 本地优先、可移植、数据自己掌控 | 要自己写 Dataview 查询；无开箱即用的趋势/预警逻辑 |
| Day One | dayoneapp.com | 日记/Journal 记录，照片、位置、加密 | 记录体验极佳、隐私好 | 纯记录，不做反思质量与动力趋势分析；闭源付费 |
| Habitica | habitica.com | RPG 游戏化习惯打卡 | 游戏化持续激励强 | 追踪"做没做"的二值习惯，不分析"做得怎样/动力如何" |
| Streaks / Reflectly | streaksapp.com / reflectly.app | 连续打卡 / AI 引导情绪日记 | 连续天数可视化直观；情绪量化思路好 | Streaks 只记二值连续性；Reflectly 闭源云端、无项目级预警 |

### 我拿来的部分

- 从 **Notion** 拿了：结构化字段模板的思路（把复盘拆成固定字段，降低"写什么"的决策成本）。
- 从 **Habitica / Streaks** 拿了：把"连续产出"可视化、把中断视为风险信号的激励设计。
- 从 **Obsidian** 拿了：本地优先、单文件可移植、数据归用户所有的原则。
- 从 **Reflectly** 拿了：把主观感受（动力/情绪）量化为分数以观察趋势的做法。

### 我不要的部分

- **Notion** 的云端依赖与过度通用——Pulse 要零依赖、离线可用、专注单一场景。
- **Habitica** 的纯游戏化与积分系统——它会稀释反思深度，把"深刻复盘"退化成"打卡凑分"。
- **Day One / Reflectly** 的闭源云端生态——数据必须能被用户自己导出、审计。

### 我的差异化

- **核心差异**：第一个把"动力曲线 + 产出连续性 + 连续下降"三类信号合成为**单一缓亡风险分**的 AAR 工具；为 C9 的 AAR 格式原生设计；自举——工具直接管理它自己的开发项目。
- **为什么有价值**：别人帮你看"你做了什么"，Pulse 帮你看"你还活不活得下去"。它把 CHALLENGE 里那条抽象的"缓慢死亡"洞察，第一次变成了可计算、可预警、可自我纠偏的工程系统。

## 3. 自驱动机制（C9 最关键部分）

### 为什么我会持续做这个项目

- **兴趣/好奇心**：我对一个元问题着迷——"反思真的可以被量化吗？一个人的状态能不能从数据里被读出来？"每多看一眼那条 U 型动力曲线，我就想再挖一层。这是享受过程的内在兴趣。
- **现实收益**：① 能力增长——CLI 设计、数据建模、可视化、算法阈值调参；② 直接收益——我自己的 AAR 质量与项目存活率提升；③ 影响力——开源后可能帮到和我一样的人。
- **身份认同**："我是一个**用系统把自己变强**的人"、"我是一个从零定义问题并解决的创造者，而不只是完成任务的执行者"。C9 的本质是"从有人告诉我做什么，到我告诉世界需要什么"——Pulse 就是这个身份的第一件作品。

> 动力层次自评：以**内部兴趣 + 身份驱动**为主（第 2、3 层），不依赖外部表扬。即使没人点赞，我也会继续用 Pulse 记录自己的每周。

### 如果没人监督，我如何保证推进

- **我的节奏**：每周至少 1 个可展示产出；固定每周四晚为"Pulse 时间"（60–90 分钟）；与 C8 交付高峰冲突时降频但不归零。
- **我的公开承诺**：代码开源到 GitHub，每周在 Elite20 群发一条进度（含动力分数截图）——用社会压力对抗缓慢放弃。
- **我的最低标准**：再忙的一周，至少提交 1 个 commit 或 1 条 AAR 数据记录（保证"节奏不中断"）。
- **我的"失败信号"**：若**连续 2 周无可见产出**，或**动力连续 3 周下滑且未做任何干预** → 立即触发自救：第一周砍掉所有非核心功能、把最低标准降到"1 个 commit"；若第 4 周仍无产出，则判定方向不成立，允许换一次方向，并在 AAR 中写清学到的东西。

> 提前定义"什么情况说明我已经放弃了"，是对自己的诚实。Pulse 的核心功能，正是把这个失败信号**自动化**——我用自己的工具监督我自己。

## 4. 执行方案（KSTAR）

### K（Knowledge）
- **已有知识**：Python 基础、AAR/KSTAR 方法论、用 AI 辅助开发的经验、基本的命令行工具设计。
- **需要学习**：SVG 图表生成、最小二乘趋势斜率、argparse 多子命令、阈值型预警系统的调参。
- **可拿来的资源**：Python 标准库（无需依赖）、开源可视化思路、AI 辅助编程（多轮 prompt 迭代，见 AI 日志）。

### S（Situation）
- **当前状态**：从零开始，只有一个想法和一支笔。
- **面对的约束**：每天可用时间约 1 小时；与 C8 真实项目并行（C8 高峰期会挤压时间）；无前端/可视化经验；数据靠手工录入。

### T（Task）
- **核心目标**：8 周内交付一个我自己持续使用、别人可独立运行的 AAR 预警工具，并沉淀完整的迭代与复盘证据。
- **里程碑分解**：
  - **Week 1–2（MVP → V1）**：单周解析器跑通 → 多周数据层 + 文本动力曲线。
  - **Week 3–4（V2 设计）**：SVG 折线图 + HTML 仪表盘骨架 + 缓亡预警算法设计。
  - **Week 5–6（低谷与干预）**：触发失败信号 → 降范围自救 → 预警算法落地 + 风险卡片。
  - **Week 7–8（V3 自举）**：内置数据 demo + 导出 + 单元测试 + 用 Pulse 管理自身 AAR + 8 周复盘报告。

### Â（Action Plan）
- 每个里程碑的具体步骤：先写最小可运行版本 → 立刻运行验证 → 发现 bug 就修并记录 → 写 AAR → 公开。
- 使用工具/AI：Python 3 标准库；AI 用于方案设计、代码生成、bug 定位、文档润色（**多轮迭代、prompt 逐步细化，全过程见 AI 日志**）；单元测试保证回归安全。

### R̂（Expected Result）
- **8 周后最终产出**：可运行的 Pulse 工具（CLI + HTML 仪表盘）+ 8 周数据 + 13 项测试 + 完整 AAR/AI 日志 + 开源仓库。
- **成功标准**：① 纯标准库、克隆即运行；② 单元测试全绿；③ 动力曲线与预警在真实数据上有效（能在低谷周发出预警）；④ 我自己连续使用 8 周。
- **如何验证**：运行 `python3 pulse.py demo && analyze && dashboard`；查看 W5 预警证据（应显示 critical）；审阅 8 份 AAR 的动力曲线是否真实反映起伏。

## 5. MVP（第一周产出）

- **我第一周会做出来的东西**：`赵心皓_C9_mvp.py` —— 一个读取单周 AAR JSON、提取动力分数并输出结构化文本报告的命令行脚本；配套 `sample_week.json` 与真实运行输出。
- **形态**：代码（Python 脚本，纯标准库）。
- **别人看了能理解什么**：AAR 可以被解析成可计算的数据——一行动力分数、一个文本条、一个状态判断。证明"把反思变成生命体征"在技术上可行。
- **展示方式**：命令行运行输出（`mvp_sample_output.txt`）+ Elite20 群内分享。

> MVP 不需要好看、不需要完整。它的唯一目的是证明我已经**从想法进入了行动**。第一周我就真的把它跑起来了，并当场发现并修复了一个解析 bug（把周次数字误当对象解包）——这个失败被诚实记录进了 W1 AAR。
